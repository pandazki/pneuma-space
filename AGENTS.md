# Working in this prototype

Read SCOPE.md before changing runtime behavior. REQUIREMENTS.md, DESIGN.md, and docs/adr/ explain the intent and record prototype decisions. Keep each validation perspective under its own prototype/ directory and preserve its reproducible evidence. Keep the single-host trust boundary explicit; do not describe it as secure multi-tenancy. Keep the gateway on Python's standard library; the sample uses psycopg for PostgreSQL. Keep application runtime state in `/data`, never in the container filesystem. Preserve existing volumes on updates and removal. Do not add authentication claims, cloud infrastructure, or external services without a concrete requirement. Run `python3 -m unittest discover -s tests -v` after changes and, when Docker is available, follow the README smoke test.
