## Platform

## Stack

delegated: Zero-dependency TypeScript static site generator (`site/build.ts` run directly by Node.js >= 24) outputting pure static HTML, CSS, SVG, and client-side JS into `site/dist/`, deployed via GitHub Actions (`.github/workflows/pages.yml`) to GitHub Pages at `https://pandazki.im/pneuma-space/` (base path `/pneuma-space/`). ## Users

- **AI-assisted & autonomous developers ("builders and the tools that write code for them"):** Publishing many small stateful web apps (surveys, dashboards, collaborative tools, real-time multiplayer games, scheduled workers, static sites) generated by coding agents or written by hand, without configuring databases, Redis, S3 buckets, or image builds.
- **Self-hosting engineers & platform operators:** Running PneumaSpace on a single trusted host via Docker Compose (M1), on an organization's Kubernetes cluster with upstream JWT identity and per-team tenants/quotas (M2), or via the additive hosted SaaS profile with personal spaces and revocable tokens (M3).

## Product Purpose

PneumaSpace is an agent-native micro-app runtime and stateful web application deployment platform. An app is a directory with a declarative manifest (`pneuma-space.json`) naming the infrastructure capabilities it needs (`files`, `db`, `kv`, `object`, `static`, `ws`, `cron`, `identity`, `rtc`). Publishing provisions those capabilities and assigns a stable address. The first request wakes the app on demand, idleness puts it to sleep (scale-to-zero), and its persistent state outlives every sleep, crash, and release.

## Positioning

- **"No agent inside. Built for what agents build."** The platform model has no agent, LLM, template chooser, or host integration inside the runtime; instead, it is engineered specifically for the high-density, high-churn workload of agent-authored micro-apps.
- **Upload, not a build; wake in milliseconds; sleep with state intact:** Isolate apps publish in ~6.9 s with no Docker image build, wake in 62–87 ms after sleep (460–700 ms first wake), and cost ~17–18 MiB RAM per awake worker thread. Container apps wake in ~260 ms. Static sites answer from the gateway bundle store without waking any process.
- **Zero-dependency protocol-speaking gateway & Guard isolation:** Written in Node.js LTS TypeScript with built-in modules only (ADR 0012), speaking Docker/Kubernetes HTTP APIs, SigV4 S3 (`rustfs`), PostgreSQL wire protocol (SCRAM-SHA-256), and RESP2 Redis directly. The Guard stops a hung worker in 3.5–4 s and quarantines crashing apps without taking neighbours down.
- **Bytes never pass through the app:** Object bytes move directly between browser and S3-compatible storage via presigned URLs; static bytes are served directly by the gateway.

## Operating Context

- Evaluated and read by systems engineers, full-stack developers, and agent platform builders who inspect architecture diagrams, wire contracts (`pneuma-space.json`, `PNEUMA_SPACE_*` env vars, `X-Pneuma-Space-*` headers), benchmark latencies, and ADRs before running `docker compose --profile isolate up -d` or `kubectl apply -k deploy/kubernetes`.

## Capabilities and Constraints

- **Three Runtime Lanes (ADR 0017):** `isolate` (worker thread per app in the runner service), `container` (any OCI image listening on port 8000), `static` (no process, served from bundle store).
- **Ten Declarative Capabilities (Contract 1):** `route` (implicit), `files` (`/data`), `db` (SQLite or PostgreSQL behind one URL), `kv` (Redis with per-app prefix), `object` (S3 bucket with presigned direct transfer), `static`, `ws` (WebSocket & SSE lease-keeping), `cron` (5-field schedule & on-demand triggers, at-least-once delivery), `identity` (`local` stub, `upstream` JWT, or `hosted` accounts), `rtc` (STUN/TURN via coturn).
- **Three Progressive Editions:** M1 (One Trusted Host / Docker Compose), M2 (Organization Edition / Kubernetes plane with tenants, RBAC, quotas, cluster operations, Prometheus metrics, and audit log), M3 (Hosted SaaS profile with personal tenants and revocable tokens + separate Contract 2 Fetch experiment).
- **Honest Trust Boundaries:** Never claim hostile-tenant isolation for M1 (trusted host) or M2 (cooperative organization members who may err). Hostile multi-tenant isolation belongs strictly to M3 release gates.
- **Bilingual & Dual-Theme Parity:** Full English and Chinese content switching (`en` / `zh`) and OKLCH light/dark theme support (`light` / `dark`), aligned with the platform's own console (`gateway/src/console.html` and `docs/console.md`).

## Product Principles

1. **Facts over slogans:** State exact latency thresholds, memory footprints, wire protocols, and trust boundaries; explicitly state what each edition gives up alongside what it gains.
2. **One visual & conceptual language from Console to Docs:** The documentation site and technical homepage feel like an extension of the PneumaSpace console (`:8081`) — calm, instrument-grade precision, live topology clarity, and zero decorative noise.
3. **Every fact traceable to its contract or ADR:** Link concepts directly to `docs/app-contract.md`, `docs/acceptance.md`, and `docs/adr/0001..0037` without contradicting or duplicating the source of truth.
4. **Zero-dependency self-contained engineering:** Build and ship the documentation site with the same zero-dependency Node.js TypeScript discipline as the gateway itself.
