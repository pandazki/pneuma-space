1. Start the Platform Stack (Compose Profiles)1. 启动平台服务栈（按需启用 Compose Profile）

compose.yaml:L1-L160 ADR 0030

By default, every port binds to 127.0.0.1 loopback: ingress on :8080, management console on :8081, and RustFS S3 object storage on :9000.默认配置下所有宿主机端口仅绑定 127.0.0.1 回环地址：应用入口 :8080、管理控制台 :8081、RustFS 对象存储 :9000。

Terminal: Start PneumaSpace on One Trusted Machine (M1) compose.yaml 
# Recommended: Gateway (:8080/:8081), RustFS (:9000), Redis, and the Isolate Runner service
docker compose --profile isolate up -d

# Container apps only (without the isolate runner)
docker compose up -d

# Full stack: also start PostgreSQL (for db_backend=postgres) and coturn (for WebRTC rtc capability)
docker compose --profile isolate --profile postgres --profile rtc up -d

# Or launch the M3 full hosted development stack with operator/alice/bob accounts on :58081
npm run dev:hosted
Service Presence Probe服务在线判定
How the gateway knows a profiled service is up (ADR 0030): addressOnNetwork() in gateway/src/providers.ts:L73-L81 resolves the service name with a bounded 500 ms c-ares DNS resolver and verifies the IPv4 address falls inside one of the gateway’s own container network interfaces before testing a 1 s TCP connect. Publishing an app whose runtime or capability profile is not started immediately returns 409 Conflict naming the --profile flag.网关如何判断可选服务已启动 (ADR 0030)：gateway/src/providers.ts:L73-L81 中的 addressOnNetwork() 使用 500 ms 有界 DNS 解析器，并校验解析出的 IPv4 是否落在网关自身网卡子网内（防止宿主机 Fake-IP 代理误导），再做 1 秒 TCP 连接探测。若对应 profile 未开启，发布将立即返回 409 Conflict 并提示所需的 --profile 参数。

2. Scaffold & Publish Your First Stateful Micro-App2. 初始化并发布你的第一个有状态微应用

cli/appctl.ts:L129-L180 templates/app/src/server.ts:L1-L22

appctl init copies templates/app (an isolate app by default). Publishing an isolate directory installs production dependencies without scripts and uploads a tar bundle in ~6.9 s.appctl init 默认拷贝 templates/app（Isolate 运行时模板）。发布 Isolate 目录时无需构建 Docker 镜像，自动在临时副本中执行 npm ci --omit=dev --ignore-scripts 并上传代码包，约 6.9 秒即可访问。

Terminal: Initialize, Publish & Open cli/appctl.ts 
# 1. Scaffold an isolate app (use --container to add a Dockerfile, or --static for a static site)
node cli/appctl.ts init myapp
cd myapp

# 2. Inspect pneuma-space.json and src/server.ts (templates/app/AGENTS.md is the complete guide)
cat pneuma-space.json

# 3. Publish to the gateway; --owner is required on first publish (or export PNEUMA_SPACE_OWNER=user:me)
node ../cli/appctl.ts publish myapp . --owner user:me

# 4. Visit the app (wakes on first request in 460-700 ms; subsequent wakes after sleep take 62-87 ms)
open http://127.0.0.1:8080/apps/myapp/
open http://127.0.0.1:8081/

What happens during appctl publish:appctl publish 在底层依次完成了什么：

  • Client-side bundling (cli/appctl.ts:L107-L157): For an isolate app, codeBundle() copies the directory following symlinks that stay inside the root, excludes .git, node_modules, data/, .env*, .npmrc, and *.test.*, runs npm ci --omit=dev --ignore-scripts, packs a deterministic ustar archive, and uploads it via POST /api/bundles.客户端安全打包 (cli/appctl.ts:L107-L157)：对于 Isolate 应用，codeBundle() 跟随目录内软链并跳过越界软链，自动剔除 .git、node_modules、data/、.env*、.npmrc 与测试文件，执行 npm ci --omit=dev --ignore-scripts 后打包上传至 POST /api/bundles。
  • Idempotent release key (gateway/src/model.ts:L119-L135): The gateway computes release_key = sha256(canonicalJson({ image, manifest, bundle })). If the app is already registered with the same release_key, publish returns the current release immediately with zero side effects (INV-6, AC-P-2).幂等版本摘要 (gateway/src/model.ts:L119-L135)：网关计算 release_key = sha256(canonicalJson({ image, manifest, bundle }))。若应用处于 registered 且 release_key 未变，重复发布直接返回当前 Release，不产生任何冗余操作 (INV-6, AC-P-2)。
  • Quota reservation & Provider convergence (gateway/src/registry.ts:L247-L289): Under the tenant row lock (ADR 0028), missing files and sqlite bindings are reserved as suspended and checked against storage_gb. Then each declared resource Provider runs ensure() outside the DB transaction, followed by the atomic commit of Release, Trigger, and Binding state.配额预留与 Provider 收敛 (gateway/src/registry.ts:L247-L289)：在租户行锁下（ADR 0028）先插入 suspended 占位行并校验 storage_gb 与 apps 配额；随后在数据库事务外对每项资源能力执行幂等的 provider.ensure()，最后在单事务中原子提交 Release、Trigger 与 Binding 状态。

3. Run & Test Your App Locally Without Docker3. 在本地无需网关直接运行与调试应用

templates/app/AGENTS.md:L85-L100 templates/app/sdk/serve.ts:L1-L90

Because the app contract is pure environment variables and HTTP headers, any app runs directly on your machine with node src/server.ts.由于 PneumaSpace 的应用契约完全由标准环境变量与 HTTP 请求头组成，你可以在本机直接用 node src/server.ts 启动并测试任何应用。

Terminal: Local Execution & Simulated Identity / Trigger Headers templates/app/AGENTS.md 
npm ci && npm test
mkdir -p data

# Run your app directly on port 8000 with SQLite and /data bindings
PNEUMA_SPACE_APP=dev \
PNEUMA_SPACE_RELEASE=0 \
PNEUMA_SPACE_FILES_DIR=./data \
PNEUMA_SPACE_DB_URL=sqlite://$PWD/data/app.sqlite3 \
  node src/server.ts

# In another terminal: simulate an authenticated owner request through the gateway
curl -H 'X-Forwarded-Prefix: /apps/dev' \
     -H 'X-Pneuma-Space-Subject: user:ann' \
     -H 'X-Pneuma-Space-Name: Ann' \
     -H 'X-Pneuma-Space-Owner: 1' \
     http://127.0.0.1:8000/

# Simulate a scheduled or on-demand trigger delivery
curl -X POST \
     -H 'X-Pneuma-Space-Delivery: d-local-1' \
     -H 'X-Pneuma-Space-Attempt: 1' \
     http://127.0.0.1:8000/_pneuma-space/trigger/tick

appctl talks to PNEUMA_SPACE_ADMIN (default http://127.0.0.1:8081) and sends PNEUMA_SPACE_TOKEN as Authorization: Bearer. Exit codes: 1 = usage, 2 = manifest error, 3 = admin API error, 4 = build/bundle/push failure.appctl 访问 PNEUMA_SPACE_ADMIN（默认 http://127.0.0.1:8081），并将 PNEUMA_SPACE_TOKEN 作为 Authorization: Bearer 发送。退出码固定为：1 = 参数用法错误，2 = 清单语法错误，3 = API 错误，4 = 本地打包或镜像构建/推送失败。
