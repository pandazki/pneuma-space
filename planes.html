Kubernetes is a deployment plane, not a runtime (ADR 0019). Setting PNEUMA_SPACE_PLANE=kubernetes swaps exactly four seams in main.ts while Lifecycle, Runtimes, AppGuard, DeliveryScheduler, Ingress, PlatformRegistry, and all CapabilityProviders remain 100% shared.Kubernetes 是部署平面，而不是运行时（ADR 0019）。在组合根 gateway/src/main.ts 中，切换 PNEUMA_SPACE_PLANE=docker|kubernetes 仅替换四个底层适配器接缝，而 Lifecycle、Runtimes、AppGuard、DeliveryScheduler、Ingress、PlatformRegistry 与全部 Provider 实现 100% 共用同一份代码。

2. Multi-Replica Coordination, Advisory Locks & Leader Duties2. 多副本 PostgreSQL 协同、咨询锁与领导者职责 (ADR 0020, ADR 0025)

gateway/src/store-pg.ts:L1-L240 gateway/src/instances.ts:L1-L255 ADR 0025
  • Connection budget per gateway replica (ADR 0025 §6): Each replica opens an 8-session query pool, up to 4 on-demand command sessions (PNEUMA_SPACE_STORE_COMMANDS=4) for Store.exclusive(appName) and Store.exclusiveBundle(bundleId) advisory locks, and 1 dedicated session that executes LISTEN pneuma_space and holds the leader advisory lock. Three replicas use at most 39 PostgreSQL connections (require session-level connections, never transaction-mode PgBouncer).每副本确定性连接预算 (ADR 0025 §6)：每个网关副本维护一个 8 会话查询池、至多 4 个按需命令会话（承载 Store.exclusive 应用名锁与 Store.exclusiveBundle 包锁）以及 1 个专用常驻会话（负责 LISTEN pneuma_space 变更通知与领导者锁）。3 副本总计最多使用 39 条 PostgreSQL 连接（需会话级连接，不经过事务模式 PgBouncer）。
  • Trigger-driven cache invalidation (ADR 0025 §5): Database row triggers fire NOTIFY pneuma_space on commit with four payload shapes: app/<name> (rebuilds RouteView if app.version is newer), policy (reloads global Policy), instance/<appId> (refreshes instance and guard mirror rows), and tenant/<name> (clears the 30 s membership & token cache in Authority).数据库行触发器驱动的实时失效 (ADR 0025 §5)：数据库行级触发器在事务提交时向 pneuma_space 通道发送四种通知：app/<name>（按版本号递增重建内存 RouteView）、policy（刷新全局策略）、instance/<appId>（刷新实例与 Guard 镜像）以及 tenant/<name>（立即清空 Authority 的 30s 成员与令牌缓存）。
  • Correctness never depends on the leader (INV-11): The replica holding pg_try_advisory_lock on pneuma-space.leader runs periodic background chores: the idle reaper, DeliveryScheduler.tick(), takeover of transitions started by replicas not seen for DEAD_MS = 10_000, orphan Pod/worker cleanup, provider convergence, and retention sweeps. Even if two replicas briefly think they lead, every transition is a CAS on (runtime, state, epoch).正确性绝不依赖领导者 (INV-11)：持有 pneuma-space.leader 咨询锁的副本负责执行周期性后台任务：闲置回收、定时触发调度、接管失联超过 10 秒（DEAD_MS）的死副本转换、孤儿 Pod/worker 清理与观测数据清扫。即便发生领导权切换或脑裂，单实例不变量仍由 instance 行上的 CAS 条件更新严格保证。

Two-namespace boundary (deploy/kubernetes/00-namespaces.yaml & 60-network-policies.yaml): Platform components (3 gateway replicas, runner StatefulSet, platform store, Redis, RustFS, coturn) run in namespace pneuma-space. Container app Pods and their PVCs run in pneuma-space-apps with ExternalName Services resolving short names (postgres, redis, rustfs). NetworkPolicies guarantee that only the gateway can reach instance Pods on port 8000, an instance Pod can reach a platform data service only if it carries pneuma-space.reach.<service>: "1", and no app Pod can ever reach another app Pod, the platform database, or the Kubernetes API (AC-K8S-9).双命名空间与网络隔离 (deploy/kubernetes/00-namespaces.yaml & 60-network-policies.yaml)：平台组件（3 副本网关、runner StatefulSet、平台库、Redis、RustFS、coturn）运行在 pneuma-space 命名空间；应用实例 Pod 与 PVC 运行在 pneuma-space-apps 命名空间。NetworkPolicy 强制保证：只有网关能连应用实例的 8000 端口；实例只有带 pneuma-space.reach.<service>: "1" 标签才能访问自己声明的数据服务；实例之间不可互访，且绝不可达平台数据库与 K8s API (AC-K8S-9)。

4. M3 Full Hosted SaaS Profile & Hybrid Origin TLS (ADR 0036, ADR 0037)4. M3 完整托管 SaaS 模式与 Caddy 源站 TLS 架构 (ADR 0036, ADR 0037)

deploy/hosted/README.md:L1-L71 gateway/src/identity-hosted.ts:L1-L220 ADR 0037

With PNEUMA_SPACE_IDENTITY=hosted (ADR 0036), PneumaSpace adds self-service GitHub OAuth sign-in, automatic personal tenant provisioning (default quota: 5 apps, 2 awake instances, 2000 CPU millis, 1024 MiB RAM, 5 GiB storage), host-only HttpOnly session cookies with CSRF verification, single-use browser-bound private-app grants, and scoped expiring deployment tokens (read, publish, invoke, remove, manage) on top of the full Contract 1 platform.启用 PNEUMA_SPACE_IDENTITY=hosted（ADR 0036）后，平台在完整保留契约 1 全部能力与原控制台的基础上，新增 GitHub OAuth 登录、首次登录幂等创建个人私有空间（默认配额：5 个应用、2 个并发唤醒实例、2 核 CPU、1024 MiB 内存、5 GiB 存储）、带 Origin 与 CSRF 校验的 HttpOnly 会话、单次绑定浏览器的私有应用访问凭据（Grant），以及支持过期时间、权限域与指定 AppId 限制的程序令牌。

Why Hybrid Origin TLS uses DNS-only + Caddy instead of Cloudflare HTTP Proxy (ADR 0037): Ordinary Cloudflare HTTP proxying imposes request body upload caps and origin read timeouts that break Contract 1’s unbounded streaming bodies and 6-hour WebSocket idle leases. The Kubernetes hosted overlay (deploy/hosted/kubernetes/) therefore uses Cloudflare DNS-only records pointing to a dedicated Caddy LoadBalancer Service that terminates TLS at the origin for the control host (:8081), wildcard apps host (:8080), and direct object storage host (:9000).为什么采用 DNS-only + Caddy 源站终止 TLS (ADR 0037)：Cloudflare 普通橙云 HTTP 代理对上传请求体大小和源站超时有限制，会破坏契约 1「无上限流式请求体」与「6 小时 WebSocket 长连接」的承诺。因此托管 K8s 叠加层（deploy/hosted/kubernetes/）使用 Cloudflare DNS-only 记录直指集群负载均衡器，由 전용 Caddy Deployment 在源站终止控制域名（转 8081）、通配应用域名（转 8080）与对象存储域名（直转 rustfs 9000）的 TLS。
