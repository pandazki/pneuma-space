Capabilities, Providers & Wire-Protocol Provisioning十大基础设施能力与 Provider 线协议供应机制

shared/catalog.ts:L22-L50 gateway/src/providers.ts:L1-L681 ADR 0005

In PneumaSpace, a new capability is one row in CAPABILITIES and one Provider implementing four idempotent operations: ensure, inject, suspend, and destroy. There are no provisioning Jobs, no docker exec scripts, and no third-party npm database drivers in the gateway.在 PneumaSpace 中，新增一项基础设施能力只需在 CAPABILITIES 表中加一行，并实现一个包含 ensure、inject、suspend、destroy 四个幂等动作的 Provider。网关内没有任何外部供应任务（Job）、没有 docker exec 脚本，也不引入任何第三方 npm 数据库驱动。

1. Runtime-Neutral & Plane-Neutral Providers (ADR 0005, ADR 0017, ADR 0019)1. 对运行时与部署平面完全无感的 Provider 设计

gateway/src/providers.ts:L103-L138 gateway/src/providers.ts:L355-L370
  • Providers never learn which runtime an app uses: StorageProvider.inject() returns an abstract storage binding { id: "pneuma-space-files-", target: "/data", env: { PNEUMA_SPACE_FILES_DIR: "{dir}" } }. DockerDriver realizes it as a Docker volume mount, PodDriver realizes it as a Kubernetes ReadWriteOnce PVC mount, and IsolateDriver realizes it as a directory inside the runner volume (/data/apps/<id>/storage/<storage-id>).Provider 不知道应用用哪种运行时：StorageProvider.inject() 只给出中立的存储绑定描述（存储 ID、挂载目标与带 {dir} 占位符的环境变量模板）。容器驱动将其落地为 Docker Volume 或 K8s PVC 挂载，Isolate 驱动将其落地为 runner 持久卷内的子目录。
  • Providers never learn which deployment plane runs the platform: Each Provider declares a read-only service property ("postgres" | "redis" | "object" | "coturn" | null). Registry puts it into Injection.services, and on the Kubernetes plane PodDriver turns each service into a Pod label pneuma-space.reach.<service>=1 enforced by NetworkPolicy (ADR 0019 §10, AC-K8S-9).Provider 不知道当前是 Docker 还是 K8s 平面：每个 Provider 仅声明一个只读的 service 属性（连哪个后端服务）。K8s 平面的 PodDriver 据此为实例 Pod 打上 pneuma-space.reach.<service>=1 标签，由 NetworkPolicy 精确放行该应用已声明的数据服务（未声明的数据库或 Redis 在网络层直接不可达，AC-K8S-9）。
  • ensure is both create and resume: Every operation is safe to run twice. When an app is removed, remove() sets its bindings to suspended and calls provider.suspend(). When the app is republished, provider.ensure() converges backend drift and re-enables the binding.ensure 既是创建也是恢复：所有四个方法均可重复执行。应用 remove 下线时，所有绑定置为 suspended（禁用凭据但保留数据）；重新发布时再次调用 ensure 即可恢复为 active，无需单独的 resume 方法。

3. Storage & Relational DB Provisioning: Pinning db_backend & Wire SQL3. 存储与关系数据库供应：db_backend 锁定规则与线协议建库

gateway/src/providers.ts:L103-L199 gateway/src/registry.ts:L242-L246

When an app declares db for the first time, Registry.publish pins the current global policy.db_backend (default "sqlite") into that app’s policyOverride.db_backend (gateway/src/registry.ts:L243). Changing the global db_backend later affects only newly created apps; switching an existing app’s database engine requires an explicit per-app policy update (appctl policy <name> db_backend=postgres), which provisions the new Binding, suspends the old one, and retires the running instance without migrating data (INV-2, AC-FORM-1).当应用首次声明 db 能力时，Registry.publish 会将当时的全局 policy.db_backend（默认 "sqlite"）写入该应用的 policyOverride.db_backend（gateway/src/registry.ts:L243）。此后修改全局默认引擎只影响尚未绑定数据库的新应用；要为已有应用切换引擎，必须显式执行 appctl policy <name> db_backend=postgres，此时平台会供应新引擎的 Binding、将旧引擎置为 suspended 并退役实例（两套数据各自保留，不自动迁移数据，见 AC-FORM-1）。

gateway/src/providers.ts:L162-L198 — PostgresProvider Provisioning Over Built-In pg.ts Wire Client PostgresProvider 
async ensure(app: AppId, current: Resource | null): Promise<Resource> {
  await requireService(this.#probe, 'postgres', 'postgres', this.kind);
  const role = `app_${app}`;
  const password = current?.password ?? secret();
  await this.#sql(async (session) => {
    if (!(await exists(session, 'SELECT FROM pg_roles WHERE rolname = $1', role)))
      await session.simple(`CREATE ROLE ${quoted(role)}`);
    await session.simple(`ALTER ROLE ${quoted(role)} LOGIN PASSWORD ${literal(password)}`);
    if (!(await exists(session, 'SELECT FROM pg_database WHERE datname = $1', role)))
      await session.simple(`CREATE DATABASE ${quoted(role)} OWNER ${quoted(role)}`);
    await session.simple(`REVOKE CONNECT ON DATABASE ${quoted(role)} FROM PUBLIC`);
  });
  return { role, database: role, password };
}

5. Content-Addressed S3BundleStore & Bundle Exclusion Lock (ADR 0028)5. 内容寻址 S3BundleStore 与并发清除互斥锁 (ADR 0028)

gateway/src/providers.ts:L374-L513 ADR 0028

Both static sites and isolate code bundles are stored in the pneuma-space-bundles bucket under their full tar SHA-256 digest (<sha256>/). S3BundleStore.put() unpacks regular files from ustar/pax/GNU tar archives via the built-in generator tarFiles(), uploads each file with its MD5 ETag and MIME Content-Type, stores the raw archive at <sha256>/_pneuma-space/bundle.tar (so the isolate runner can fetch it via a 600 s presigned GET URL without holding S3 credentials), and writes <sha256>/_pneuma-space/index.json last as the commit marker.静态站点产物与 Isolate 代码包均以整个 tar 包的 SHA-256 摘要为键存储在 pneuma-space-bundles 桶中。S3BundleStore.put() 通过内置的 tarFiles() 生成器解析 ustar/pax/GNU tar 归档，逐个写入静态文件并记录 ETag 与 Content-Type，将原始归档存于 <sha256>/_pneuma-space/bundle.tar（供 Isolate runner 通过 600s 预签名 GET URL 直接拉取，无需让 runner 持有对象存储凭据），并在最后写入 index.json 作为完整落盘标记。

Preventing publish/purge races across replicas (ADR 0028 §2): Committing a Release that references a bundle ID and deleting that bundle during another app’s purge both acquire Store.exclusiveBundle(bundleId, fn) (PostgreSQL session advisory lock pg_advisory_lock(3, hashtext(bundle)), ordered strictly after the app-name lock).跨副本防竞态互斥 (ADR 0028 §2)：提交引用某 bundle 的 Release 与在另一应用 purge 时删除该 bundle，均通过 Store.exclusiveBundle(bundleId, fn)（在 PostgreSQL 上取会话级咨询锁 pg_advisory_lock(3, hashtext(bundle))，锁序严格遵循「先应用名、后 bundle」）互斥，彻底杜绝并发发布期间 bundle 被误删。
