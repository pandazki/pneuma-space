# 用户故事

按应用类型组织。类型的差别只在于对平台能力的不同要求，能力编号见 `docs/alignment-review.md`。每条故事有稳定 ID、角色、阶段和验收提示。领域模型必须能让每条 M1 故事只用模型里定义的概念讲通。

角色：开发者写应用并发布；访问者打开应用；外部程序以自己的身份调用应用，例如另一台服务；运营者运行平台。平台不区分开发者是人还是程序。

| US-P-2 | 开发者 | 我发布新版本，地址、数据和能力绑定都不变。 | M1 | 发布是幂等的版本替换 |

| US-P-4 | 访问者 | 应用几天没人访问，我再打开仍能用，首次打开慢几秒，之前的数据都在。 | M1 | 闲置停止后唤醒 |
| US-P-5 | 运营者 | 一条 Compose 命令起平台，得到管理后台。 | M1 | 单命令启动 |
| US-P-6 | 运营者 | 管理后台除总览外只有项目：列表、发布、版本、能力绑定、策略、运行态（含 Lease 计数和进入该状态的时间）、最近访问、请求数、错误数、触发投递记录、容器日志、移除、清除。 | M1 | 后台没有总览和项目以外的东西 |
| US-P-7 | 运营者 | 我改全局闲置策略，或给某个应用单独设策略，不重新发布应用。 | M1 | 策略是平台状态 |
| US-P-8 | 运营者 | 我放了几百个应用，绝大多数在睡，机器资源有界，列表仍然快。 | M1 | 列表不逐容器查询；CPU 和内存随运行数增长，磁盘和后端元数据随注册数增长 |
| US-P-9 | 运营者 | 我移除一个应用，地址失效，数据保留；我清除它，数据才删除。 | M1 | 移除和清除是两个动作 |
| US-P-10 | 运营者 | 我重启平台，注册、版本、策略、数据都在，应用按需被唤醒。 | M1 | 平台状态持久化 |
| US-P-11 | 运营者 | 我把平台部署到多节点，应用清单和契约不变。 | M2 | 运行面可替换 |
| US-P-12 | 运营者 | 我给不同租户分配资源并计量。 | M3 | 租户概念可加入 |
| US-P-13 | 运营者 | 我打开后台先看到总览：平台服务是否在线、多少应用在跑和为什么在跑、唤醒和请求是否正常、触发是否积压或失败、机器还剩多少资源、平台最近发生了什么。总览在打开期间是活的：应用醒来、睡去、投递失败时页面随之变化，不用刷新；主机空闲时页面静止。 | M1 | 总览只用网关内存里的数据，重启清零；活的总览靠浏览器轮询，推流、每应用的分时统计和每容器的资源用量是 M2 |
| US-P-14 | 运营者 | 我打开实时页，看到请求一条条进来：哪个应用、什么路径、状态、耗时、是否冷启动、谁发的；事件和错误在同一页流式滚动；我在顶部按应用、类别、状态、路径过滤；点开一条看全部字段。 | M1 | 请求记录只在网关内存，最近 1000 条，重启清零；访问日志落盘是 M2 |
| US-P-16 | 运营者 | 我打开拓扑页，一幅图看懂服务是怎么跑起来的：访客到网关到每种运行时到平台服务，每个应用在它的运行时泳道里亮着或睡着；哪个服务不通、哪些应用因此受影响、哪个应用被隔离，一眼看到并能就地处置；点一种运行时看它的架构说明；切到连线视图，点一个应用看它从访客经网关中间件到它启用的每个能力和服务的整条路径。 | M1 | 零 Docker 调用，只用网关内存和列表（ADR 0018）；每应用到每服务的精确依赖看详情页 |
| US-P-15 | 应用作者 | 我发布一个 isolate 应用不构建镜像，秒级发布，首次请求在 1 s 内有应答；它卡死时平台杀掉它并在下次请求重启，反复卡死时隔离并告诉我，别的应用不受影响；我在后台解除隔离。 | M1 | 运行时可插拔（ADR 0017）；isolate 需要启用 runner 服务；容器仍是任意运行时的选项 |

## 必须成立的不变量

验证领域模型时，每条都要能指出由哪个概念保证。

| ID | 不变量 |
| --- | --- |
| INV-1 | 应用地址只由应用名决定，与容器、版本、节点无关。 |
| INV-2 | 应用数据（文件卷、数据库、键值存储）的生命周期长于容器、版本和注册，只有清除才删除。 |
| INV-3 | 闲置停止不会中断进行中的请求、长连接、流和触发执行。 |
| INV-4 | 送往休眠应用的触发会唤醒它并至少投递一次；重试有上限，失败可见。 |
| INV-5 | 身份上下文由平台在服务端生成，应用收到的身份头不可能来自浏览器伪造；主体的可信度由身份提供者决定。 |
| INV-6 | 发布同名应用是版本替换，不创建新地址，不丢数据，不改能力绑定以外的东西。 |
| INV-7 | 平台重启后，所有注册、版本、策略、能力绑定和数据保持不变。 |
| INV-8 | 应用代码只依赖契约固定的协议（SQL 连接 URL、Redis 协议、S3 协议、WebSocket 和 SSE），不依赖谁在哪里提供它们；SQL 文本须用两种数据库共有的子集。 |
| INV-9 | 每个能力实例由一个 Provider 或一个组件负责；应用只通过注入的配置使用它。 |
| INV-10 | 对象和静态资源的字节由平台提供，不经过应用容器，也不要求应用处于运行态。 |
