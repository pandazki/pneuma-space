# 0042：独立 Cloudflare 版本

状态：接受。2026-11-13，写于未公开的分支，编号 0033；并入主干时改为 0042。[ADR 0041](0041-cloudflare-m1-plane.md) 修订它的定位（属于 M1）和“源码留在本地分支”一句。用户要求把 PG、Redis 的用途迁到 Cloudflare 对应服务，随后明确要求独立版本。控制台在运营者配置的控制域名上，`/admin` 是平台管理员后台，`/dashboard` 是租户界面，注册采用邀请制。

## 决定

在 `cf/` 实现独立版本。它不修改 M1、M2 和原托管版，不继承 Fetch 实验的功能限制，也不声称原 PostgreSQL、Redis 或 POSIX 文件接口无修改兼容。这个选择修订 [ADR 0036](0036-additive-hosted-platform.md) 对该独立版本的共用实现要求。原产品要求继续约束原部署。

Worker 负责 HTTPS、认证、控制台和入口。D1 保存用户、邀请、会话、成员、令牌、租户及应用目录。每个不可变 AppId 对应一个 SQLite Durable Object，拥有应用版本、生命周期、运行时、持久数据、任务和诊断。该对象的 SQL 空间属于应用。平台状态、世代、键值和文件使用 SQL 无法访问的隐藏 KV。同步事务内先检查世代再执行数据操作，期间不执行外部 IO。

应用对象是生命周期真相。D1 的状态摘要只是带观察时间的目录投影，操作和精确详情必须访问应用对象。计算只经 Runtime.acquire 启动固定 Node 镜像，镜像从 R2 取得不可变应用包。容器文件系统只存可重建制品和临时文件。应用通过限定 AppId、世代和启动身份的内部服务调用持久能力，不获得云账户凭据。通用 Node 包与静态站点共用发布入口。

R2 保存制品、静态资源和对象。对象的上传下载使用短时签名地址，字节不经过应用或 Worker。持久小文件使用原生文件接口和 Durable Object 存储，不伪装 `/data`。定时和重试使用持久闹钟，实时消息使用 WebSocket。RTC 接真实的 TURN 服务，未配置时明确拒绝依赖它的发布。

平台管理员和租户角色在服务端授权。高熵访问密钥只存散列，邀请限时、一次性兑换，登录产生可撤销会话。控制台写操作检查精确 Origin 和 CSRF。每个应用使用独立的 Custom Domain、独立应用会话和一次性交换，应用代码不获得控制台凭据。默认关闭外网出站，只放行自己的内部能力服务。

发布、下线和恢复保留所有数据。清除只能从 removed 开始并确认应用名，终态标记永不被迟到请求移除。已经发出的对象签名地址在到期前仍有效，清除任务必须在最后一个写票据到期后再次清理，不能提前报告完成。SQL 和文件恢复不得直接回滚生命周期世代。

原生接口和范围只在 [CF 应用契约](../../cf/docs/app-contract.md) 定义，验证条目只在 [CF 验收](../../cf/docs/acceptance.md) 定义。写下时用户要求源码留在本地分支；ADR 0041 之后公开在主干。

## 取舍

选择一个应用对象作为事务边界，避免四个数据对象之间的下线与清除协调。接受单对象的容量与吞吐上限，内测配额设得更低。没有常驻数据库、Redis 或本机依赖。

复用已有身份过滤、签名、发布日志和命名规则的做法。原 Node 网关的事务回调、领导者和进程接口不直接映射到 D1。控制台展示实际 CF 资源和应用观测，不虚构 Kubernetes 节点或未采集的监控指标。

独立邀请制版本不等于公开敌对租户隔离已经通过。每项声明均须通过实际 CF 验收，不以旧问卷或本地模拟的成功替代。
