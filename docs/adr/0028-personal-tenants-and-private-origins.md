# 0028：个人租户、自助注册与私有应用源

状态：接受。2026-11-11。

## 背景

[ADR 0022](0022-tenants-and-access.md) 已把 Tenant 定义为未来客户边界，但 M2 由管理员建租户，默认应用可供整个组织访问。[ADR 0021](0021-trusted-upstream-identity.md) 的浏览器边界不防恶意应用作者。公网自助注册不能沿用这些假设。

## 决定

私有空间就是 Tenant。认证适配器返回提供者与不可变主体，账户目录为它保留稳定的内部 UserId、TenantName 和注册意图。注册先保存意图，再由 Registry 幂等创建租户、用户和首个管理员。成功后才签发会话。它是可重试的跨存储操作，不是跨对象事务。显示名或邮件地址不用于合并账户。

Cloudflare 按外部身份散列分配目录对象，按 TenantName 分配 Registry 对象，按 AppId 分配记录对象。注册容量账本只出现在新注册路径；已注册用户登录和应用请求不依赖一个全局协调者。首版不要求邀请码，不开放团队成员管理。

云端名称在租户内唯一。地址由应用名及平台生成的租户名共同决定，具体格式只在应用契约中定义。它是对 INV-1 的云端修订，保留“版本和执行位置不改变地址”。M1、M2 的全局名称和地址不变。

云应用固定为租户私有，拒绝 `org` 和 `public`。认证发生在应用代码及静态文件之前。个人令牌带租户、动作、可选 AppId 范围和到期时间，只存随机秘密的散列。令牌不能签发令牌、改成员或清除数据。每次准入读取权威状态；吊销不依赖正向缓存。已准入的有界请求可以完成，待发布操作提交前重新验证凭据。

控制台和应用后缀使用不同的可注册域名。控制台与应用分别使用 host-only、Secure、HttpOnly 的 `__Host-` 会话。应用登录经平台保留路径交换短时、一次性授权码，绑定精确应用源、AppId、浏览器 nonce 和父会话。代码收到请求前，入口删除平台凭据和保留身份头；响应不能覆盖平台 cookie 或设置父域 cookie。控制台写操作验证 Origin 和 CSRF，应用的 cookie 写请求验证精确 Origin。

身份的首个实现使用 GitHub OAuth code、state 和 S256 PKCE，不请求仓库权限，也不保存上游 access token。替换身份提供者时迁移目录映射或执行明确的账户关联，不按邮箱猜测身份。产品页面不显示云账户或基础设施标识。

## 被拒绝的方案

- 为每个新用户授予平台管理员，以复用旧建租户接口。
- 在 `sighted` 中隐式注册租户，混淆观察身份与授权开户。
- 一个 Registry 对象处理所有租户的日常请求。
- 只修改前端默认值，保留服务端 `org` 访问语义。
- 把控制台会话或部署令牌交给应用，用它完成应用登录。

## 后果

M3 的默认访问、名称查找、登录会话和凭据范围是显式的新契约。注册容量、请求和存储限额控制免费测试范围，不构成货币费用上限。域名、OAuth 和真实云端边界未验收时，不开放任意用户上传。
