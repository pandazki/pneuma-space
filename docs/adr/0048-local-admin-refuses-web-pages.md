# ADR 0048：local 模式的管理 API 拒绝网页能发出的请求

状态：接受。2026-11-26。补充 ADR 0001 和 DESIGN 第 4 节"不做管理端口认证"：仍然没有认证，只拒绝浏览器里的网页能发出、而控制台和程序都不会发出的请求。

## 背景

`local` 下管理 API 不认证，每个请求都是平台管理员（ADR 0022 第 4 条）。回环绑定挡住了别的机器，挡不住这台机器上的浏览器，有两条路：

- **跨站写。** 任何网页都能向 `127.0.0.1:8081` 发不触发预检的 POST（没有自定义请求头，`content-type` 是 `text/plain`）。网页读不到答复，但写已经执行，例如移除非受管应用、停止任意应用的实例（#43）。平台托管的应用页面也是这样的网页，它和控制台同站不同源。
- **DNS 重绑定。** 攻击者的名字先解析到自己的服务器，页面加载后改解析到 127.0.0.1，页面再向自己的名字发请求就到了管理端口。这些请求是同源的：写的 `Origin` 等于它的 `Host`，读能拿到答复，包括应用列表、日志和审计。

`upstream` 有 ADR 0021 第 7 条的 `Sec-Fetch-Site` 检查，托管模式有 control origin 和 CSRF，只有 `local` 没有。不是浏览器的调用方不能受影响：本机的 `appctl` 用 `127.0.0.1`；同一 compose 网络上的其他容器用服务名，例如 `http://gateway:8081`（agent-app-governance 的 local 版、pneuma-framework 的示例 Host）。

## 方案

1. **只看 `Sec-Fetch-Site` 和 `Origin`。** 挡住跨站写，挡不住重绑定。
2. **`Host` 只认 `localhost`、`127.0.0.1`、`[::1]`，所有请求都查**（示例 Host 对自己 API 的做法）。挡住重绑定，但按服务名访问的容器全部被拒，各自要加配置。
3. **`Host` 只对带浏览器标记的请求查。** 浏览器的写总带 `Origin`，重绑定的写被拒；但重绑定页面对同源的 GET 不带 `Origin`，对 `http` 上的非回环名字也不带 `Sec-Fetch-*`，读照样泄漏。
4. **按名字能不能被网页指过来分。** IP 地址和 `localhost` 不经 DNS，任何请求都接受；单标签名（compose 服务名）只在这台机器或它的网络上解析，接受不带浏览器标记的请求；其他名字任何人都能注册，拒绝，除非运营者列出。

选方案 4。

## 决定

1. **只在 `local`，在路由之前。** 除 `/healthz` 外的每个请求先过下面两条，不过就答 403，不进路由，不写审计：审计只追加，记下它们等于让任何网页都能让它无限增长。`upstream` 和托管模式不变。
2. **名字。** `Host` 去掉端口后必须是 IP 地址（含 `[::1]`）、`localhost`，或 `PNEUMA_SPACE_ADMIN_HOSTS`（逗号分隔的主机名，不带协议和端口，默认空）里的名字。请求既不带 `Origin` 也不带 `Sec-Fetch-Site` 时，单标签名（字母、数字、`-`、`_`，没有点）也接受。读写都一样。
3. **写。** `GET`、`HEAD` 以外的请求：带 `Sec-Fetch-Site` 时必须是 `same-origin` 或 `none`；带 `Origin` 时必须等于 `http://` 或 `https://` 加上 `Host`。
4. **读不另加规则。** 管理 API 不发 CORS 头，别的源的页面读不到答复；读得到的只有同源页面，也就是重绑定的页面，第 2 条按名字拒绝它。

理由：浏览器给每个写都加 `Origin`（Fetch 规范：`GET`、`HEAD` 以外的方法总带，可能是 `null`），页面去不掉；Node 和 Bun 的 `fetch`（`appctl`、上面两个 Host）都不发 `Origin` 和 `Sec-Fetch-Site`，Node 只发 `Sec-Fetch-Mode`。所以这两个头分得开网页和程序。重绑定需要一个攻击者的 DNS 回答得了的名字：IP 地址和 `localhost` 浏览器不查 DNS；单标签名经这台机器的解析器和搜索域，只有控制它所在网络 DNS 的人回答得了。

## 后果

- 控制台（同源）、`appctl`、按服务名或 IP 调用的容器照旧，不用改配置。
- 用带点的名字打开控制台（局域网主机名、Tailscale 名字、`host.docker.internal`）答 403，名字加进 `PNEUMA_SPACE_ADMIN_HOSTS` 后可用。程序用带点的名字调用也是 403，同样加进去。
- 留下的缺口：回答得了这台机器单标签名查询的人（局域网里的 LLMNR、恶意路由器的 DNS）能用单标签名重绑定，读到答复；写仍被拒。
- 这不是认证。本机任何程序、compose 网络上的任何容器（应用容器也在内）照样能调用管理 API，M1 的信任边界不变（`REQUIREMENTS.md`）。
- 不做：控制台页面防嵌入（`frame-ancestors`）、按 `Sec-Fetch-Site` 拒绝读。
