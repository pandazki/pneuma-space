# ADR 0007：对象由对象服务提供，静态由网关提供

状态：**M1 决定**。

决定：对象存储是 S3 兼容服务（M1 用 RustFS；MinIO 已停止维护，任何 S3 兼容服务都可以换上），发布自己的回环端口。应用拿到 bucket 和限该 bucket 的密钥。浏览器上传走应用签发的预签名 URL，直达对象服务。`public/` 前缀匿名可读，带 Range。网关不转发对象字节。静态 bundle 由网关从对象存储流式提供，因为它们必须在应用地址上；静态站点没有容器。CDN 是把 `PNEUMA_SPACE_OBJECT_PUBLIC_ENDPOINT` 指向 CDN、对象服务做源站。

理由：预签名上传本来就需要浏览器可达的存储端点，第二个端点无论如何存在；再让网关提供公开读就是同一件事的第二种做法，还把字节放进网关进程。这和 OSS 的用法一致，任何 S3 SDK 都能用。

拒绝：网关在 `/apps/<name>/_pneuma-space/o/<key>` 提供对象（单一源站、移除即停服，但字节过网关，且两种读法并存）；上传也经网关流到对象服务（500 MB 过网关进程）；应用完全看不到 S3、只拿平台 API 和令牌（五个平台端点、更多代码，失去 S3 生态）。

后果：对象和应用是两个源，bucket 需要 CORS。风险：RustFS 的管理接口能否创建限 bucket 的用户和策略要先做一次 spike；不行时退路是网关持有唯一凭据并代应用签发预签名 URL，只改 Provider，不改实体。`remove` 时 Provider 撤销匿名读策略和密钥，对象才停止对外；`purge` 才删字节。
