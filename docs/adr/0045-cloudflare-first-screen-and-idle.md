# ADR 0045：Cloudflare 承载面的首屏、空闲与唤醒记录

状态：接受。2026-11-24。修订 [ADR 0043](0043-cloudflare-first-application.md) 中“用一条指令让编程工具完成首个应用、上线、自然休眠与恢复验证”：`start` 不再等待自然休眠，由 `bench` 验证。补充 [ADR 0044](0044-cloudflare-path-routing.md) 第 3 条：控制源的根路径只属于控制台。

## 背景

拥有者打开一个由起步模板生成的应用，约 10 秒后才看到页面，样式也没生效。实测休眠后第一次请求 2.9 秒和 4.9 秒，醒着约 0.8 秒。原因有三：

- 起步模板只声明 `kv` 和 `identity`，HTML、CSS、JS 都由容器里的 Node 返回，第一个 HTML 字节也要等冷启动。平台本来就能不启动容器、从 R2 返回声明的 `static` 目录。
- 默认空闲 30 秒，几乎每次访问都是冷启动。
- 按路径寻址后，应用页面按根路径引用 `/style.css`、`/app.js`，拿到的是控制台自己的文件，状态 200。

冷启动慢在哪一段，平台此前没有记录，只能猜。

## 决定

1. **起步应用的页面外壳是静态目录。** 模板把 HTML、CSS、JS 和图标放进声明的 `static` 目录，Node 只提供数据接口。页面先画出可用的首屏，接口回来再填数据；接口慢或失败时在原处给出重试。所有地址用相对路径。技能和参考文档照此指导生成新应用。
2. **静态优先。** GET 和 HEAD 的路径若是静态目录里的文件，就在授权后从 R2 返回，应用休眠时也不唤醒；以 `/` 结尾的路径指向该目录的 `index.html`。其他请求交给 Node。规则写在 [CF 应用契约](../../cf/docs/app-contract.md)。
3. **控制台文件离开根路径。** 控制台自己的文件放在保留段下的 `/_pneuma-space/console/`。根路径只有控制台路由（`/login`、`/invite`、`/admin`、`/dashboard`、`/api/v1/`、`/downloads/`）；其他根路径一律 404。文件名不带内容散列，所以照旧 `no-store`，不标记 immutable。
4. **新应用默认空闲 300 秒。** 已有应用保留存下的策略，要改就在控制台的运行策略里改。
5. **`start` 不等待自然休眠。** 它发布、测量请求，并报告这次唤醒的各阶段用时，写明休眠与恢复尚未验证。`bench` 照 ADR 0043 验证：按应用实际的空闲策略等待自然休眠，不调用休眠操作，再访问并确认新的启动身份和保留的数据。
6. **每次唤醒记录各阶段用时。** 运行器在就绪探测的回答里带上自己的运行时长和取包、解包、应用开始监听的用时，不另开上报通道；应用单元记下预留、容器启动、确认就绪和首个响应，作为应用详情里的最近一次唤醒，并为每次唤醒写一条事件，随事件一起有界保留。控制台的运行页显示最近一次的分解。

## 被拒绝的方案

- **验证期间把空闲临时改短。** 发布令牌只有 read、publish、invoke；改策略要 manage。不为一次验证扩大令牌权限。
- **`start` 照旧等满策略时间。** 五分钟以上，编程工具会超时或中断命令，用户得到的是失败而不是应用。
- **把根路径的请求转给“最可能”的应用。** 同一个源下有多个应用，根路径无法判断属于谁；404 让写错的地址在第一次打开时就暴露。
- **静态文件由 Node 兜底返回。** 首屏仍要等冷启动，正是要去掉的那一段。

## 后果

- 起步应用的首屏不等容器；冷启动只推迟数据。按根路径引用资源的已有应用会看到 404，要改用相对地址并重新发布。
- 首次体验的直接产出是可用的应用和冷启动各阶段用时；休眠证据要用户或工具另跑 `bench`，等待时间取应用的空闲策略。控制台引导页、项目指令和技能照此改写。
- 应用醒着的时间变长，Container 计费时间随之增加。
- 唤醒记录里的容器启动段由应用单元的时钟减去运行器报告的运行时长得出，含一次就绪探测的网络往返；它说明慢在哪一段，不是精确计时。
