# ADR 0031：请求游标带进程世代

状态：**M2 决定**。取代 ADR 0024 第 5 条里游标的形状 `<replica>:<seq>,...`，以及请求环靠"游标的 seq 大于本进程最新的 seq"识别重启的做法。对应 issue #18。

决定：

1. **每个网关进程的请求环有一个世代**：进程启动时的毫秒时间，不持久化。同一个副本名的两次启动世代不同，seq 照旧每次从 1 开始。
2. **游标仍是不透明串，每个副本一项 `<replica>:<seq>@<generation>`。** 副本按自己那一项答页：世代相同，返回 seq 之后的记录；世代不同、没有世代（本决定之前的游标或手写的）、或 seq 超过本进程最新的 seq，从本进程还保留的最老记录开始，并标记这个副本 reset。游标里没有这个副本（第一次请求的空游标，或新加入的副本）不算 reset，同样从最老记录开始。同一世代里游标早于最老记录（环溢出）不算 reset，照旧从最老记录开始。
3. **`GET /api/requests` 在 `missing` 旁答 `reset`**：自所给游标以来重启过的副本名。`?local=1` 的页带本副本的世代和 reset，扇出原样转交，所以任一副本接到请求都能报告别的副本的重启。归并后游标里该副本的项换成答页的世代，seq 是保留下来的最后一条记录，一条也没保留时是 0；下一次轮询世代相同，reset 只报一次。某副本不可达时其他项照旧保留（ADR 0024 第 5 条）。
4. **实时页把 reset 画成请求流里的一行**，写明哪个副本重启、之前的记录已经没有了，样式同不可达副本的缺口行，其后是新世代的记录。同一副本的序号缺口只在同一世代里判断。

理由：只比较 seq 大小，新进程的 seq 追上旧游标之后就认不出重启，它还保留的前若干条记录被静默跳过，页面却像一条连续的流。世代给"同一条流"一个身份，判断不再依赖 seq 的大小。启动毫秒够用：同一副本名的两次启动之间隔着一次进程启动，不会落在同一毫秒；`usage` 的 `replica` 列已经用启动毫秒区分重启（ADR 0024 第 2 条）。reset 由持有那条环的副本自己判定，判定只读内存，`GET /api/requests` 仍然零 IO（AC-P-15）。

拒绝：浏览器自己看 seq 变小来判断（seq 追上之后它和网关一样认不出）；把世代并进副本名（记录、缺口行和过滤里的副本名会随每次重启变）；随机串做世代（和启动毫秒一样唯一，读日志时认不出是哪次启动）；重启后从旧游标的 seq 接着读（新旧进程的 seq 没有关系，不是跳过就是重复）。

后果：升级到本决定后，浏览器手里的旧游标在第一次轮询时被当作 reset，从最老记录重读一遍。滚动升级期间旧副本读不懂新格式的项，那几次轮询可能重复一页记录。环溢出仍由页面按序号缺口报告，不算 reset。
