# 0029：制品清除的终态栅栏

状态：接受。2026-11-11。

## 背景

[ADR 0027](0027-hosted-fetch-profile.md) 让下线使旧发布失去激活资格，但元数据的序号不能撤销已经发出的对象写入。真实文件适配器复现了这个顺序：发布停在写制品之前，下线和清除完成，旧写入随后落盘。应用没有复活，源代码却重新出现。写入后再检查无法覆盖写入完成后进程消失的情况。

## 决定

ArtifactStore 拥有每个 AppId 的不可变制品键登记和永久清除标记。Cloudflare 适配器在独立的每应用 SQLite Durable Object 中先登记摘要，再向 R2 做仅当键不存在时的写入。清除先原子关闭登记，再将所有已登记的 R2 键覆盖为不含代码的终态标记。旧写入先成功时，清除覆盖它；终态标记先成功时，旧写入的条件失败。未完成的清除可以重复执行，不删除登记或标记。

登记只在保存制品和清除时访问。读取制品不经过它。该状态属于 ArtifactStore，不属于 RecordsProvider，也不进入应用 ABI。替换适配器必须提供相同的终态保证。本地文件适配器使用 SQLite 事务串行化终态检查和同步文件写入、删除。

每次实际重试准备制品都重新消耗当天的发布额度。已经成功的幂等重放不消耗额度。应用数和制品字节的容量预留仍按逻辑操作去重。

## 后果

清除删除应用数据与代码字节，保留拒绝迟到写入所需的少量终态元数据。Cloudflare 增加一个仅用于制品登记的 Durable Object 命名空间。不增加后台清理任务，也不依赖调用者在错误后继续运行。
