# ADR 0002：稳定路径、按需运行与闲置停止

状态：**已被 ADR 0006 取代**。原型验证的闲置停止、缓存启动状态和连接失败前重试仍是 M1 设计的输入。


决定：应用通过 `/apps/<name>/` 访问；网关首次请求启动 Docker 容器，活动请求阻止闲置停止，卷在更新和移除注册时保留。发布采用操作员预构建的可信镜像。网关缓存自己已启动的容器状态；空闲停止时清除状态，连接失败时仅在请求发往应用之前尝试恢复，避免重放写请求。

验证与取舍：热路径原本每次调用 Docker start；阶段计时重现了 Docker 调用主导的慢请求，缓存后对应调用被消除。24 个冷注册、最多 3 个活动应用的重复采样中，仍观察到部分客户端等待波动，原因未确定。外部手动停止容器时，Docker DNS 可能约 4 秒才报告解析失败；该路径最终恢复，但速度仍是已知风险。自身闲置停止与正常唤醒已通过隔离网关测试。闲置停止仍在全局锁内，管理列表逐容器查询 Docker。证据：`tests/test_runtime.py`、`tests/compose_smoke.py`、`prototype/03-cold-apps/`。

限制：没有 WebSocket、流式响应、定时触发或可靠后台工作；成功唤醒不等于高可用恢复。观察样本不是容量、成本或延迟承诺。
